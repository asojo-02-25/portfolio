# ポートフォリオサイト 実装計画

作成日・最終更新日: 2026-10-26

## 1. 目的と現在地

就職活動で利用できる初版を早期に公開する。要件と画面構成をもとに、モバイルファーストで実装し、公開後にデザインや記事連携を改善する。

- 要件・掲載原稿: `docs/requirements.md`
- 画面構成: `wireframes/top.drawio`（トップ・経歴・プロジェクト・記事・スキルのスマートフォン版とPC版）
- ドキュメントとワイヤーフレームを作成済み。工程1でTypeScript・Astro・React・Tailwind CSSの環境構築に着手。
- 本書の工程と確認項目は実装に向けた計画。未決定の技術・公開先を決定済みとして扱わない。

## 2. 実装方針と初版の範囲

### 合意済みの方針

- 静的サイトとして作り、ReactとTailwind CSSを使用する。
- 公開先はGitHub PagesまたはVercelから選ぶ。
- トップと4つの詳細ページを用意し、関連リンクは共通フッターにまとめる。
- トップのカードはスマートフォン・PCともに1列。PCでは左に見出し、右に内容を置く。
- カードの移動表示は文章ではなくシンプルな右向きの記号とする。
- 経歴は年月を `2025.02` 形式とし、各出来事を枠で囲む。
- 掲載原稿を独断で修正・要約しない。トップ用と詳細ページ用の原稿を区別する。
- 記事がない状態で公開できる。初版の記事表示は「準備中」を基本とする。
- Xで共有するためのOGP画像を作り、共有用のメタデータとともに設定する。

### 記事と原稿の管理案

- 自己紹介・経歴・プロジェクト・スキルは、リポジトリ内のデータファイルで管理する案を基本とする。
- 記事はZennまたはQiitaで執筆し、サイトには媒体アイコン・タイトル・小説明などのカードを表示して本文へリンクする案を基本とする。
- 記事情報はビルド時に取得して静的出力に含める。記事取得元やアカウントが未定でも、空の記事一覧で画面実装を進める。
- 最初は再ビルドで更新する想定。定期取得や投稿に連動した自動更新は公開後の改善候補とする。
- 本文全体の取り込み、管理画面、ログイン、データベースは初版の作業対象に含めない。

## 3. 大まかな実装工程

| 工程 | 主な作業 | 完成の目安 |
| --- | --- | --- |
| 1. 構成決定・環境構築 | 言語、ビルド・静的ページ生成方法、公開先を決定。React・Tailwind CSSの開発環境と基本チェックを整備 | 開発サーバーで最小画面を表示でき、本番用の静的ファイルを生成できる |
| 2. 共通部品・ページの骨組み | ヘッダー、フッター、本文幅、見出し、カード、戻る導線、5ページのURLを実装 | 全ページ間の移動とトップへの復帰ができる |
| 3. 原稿の反映・スマートフォン版 | データファイルを整理し、トップと4つの詳細ページを順に実装 | 合意した原稿・リンク・「準備中」の表示がそろい、スマートフォン幅で読める |
| 4. PC対応・見た目の調整 | PCでのカード内配置、余白、本文幅、色、フォント、画像・アイコンを整える | スマートフォンからPCまで、横はみ出し・重なりがなく閲覧できる |
| 5. 記事連携・共有設定 | 記事取得元が決まっていれば取得処理を追加。OGP画像、タイトル、説明文を設定 | 記事の有無に応じた表示ができ、静的HTMLに共有用メタデータが含まれる |
| 6. 公開・受け入れ確認 | ビルドと必要なチェック、公開設定、実機・公開URLでの確認、README整備 | 完成条件を確認し、公開URLと更新手順を記録できる |

工程3ではトップ → 経歴 → プロジェクト → 記事 → スキルの順で進める。各工程の終了時に実装状況と残件を本書に追記する。

## 4. 工程ごとの注意点

### 環境・URL

- URL案は `/`、`/career/`、`/projects/`、`/articles/`、`/skills/`。環境構築時に確定する。
- 共有用メタデータをJavaScript実行前に読めるよう、静的HTMLとして出力する構成を選ぶ。
- 各ページのURLを直接開いた場合と再読み込みした場合にも表示できる出力・公開方法にする。
- GitHub Pagesを選ぶ場合は、リポジトリ名を含む公開パスを踏まえて内部リンク・画像パスを設定する。
- 依存パッケージの導入時に公式ドキュメントと互換性を確認し、採用構成・コマンドをREADMEに記録する。

### 原稿・素材

- トップと詳細ページに自己紹介文の表現差があるため、統一が必要なら本人に確認する。
- スキル原稿の `html. css` は、ワイヤーフレームではhtmlとcssの2項目としている。実装前に扱いを確認する。
- プロジェクト画像、技術・媒体アイコン、OGP画像の素材とデザインを決める。使用する外部素材の出典・利用条件を確認する。
- 記号のみのリンクにも、支援技術で行き先が分かる名前を設定する。
- 記事のリンクと詳細ページへのリンクが競合しない構造にする。カード内に複数リンクがある場合は、カード全体をリンクで囲まない。

### 記事取得

- ZennはRSS、Qiitaは公式APIを候補とし、実装時に取得項目・制限を確認する。
- 小説明は取得内容を確認して決め、適した抜粋がなければ本人の短文を別途管理する。
- 未設定・記事0件は正常な状態として「準備中」を表示する。
- 取得失敗は0件と区別してログに記録する。失敗時は保存済みデータを利用するなど、表示済みの記事を不意に消さない方針を実装時に決める。
- 認証情報が必要な場合はビルド環境でのみ使用し、公開ファイルに含めない。

### 工程1の実装記録

- TypeScript、React、Tailwind CSS、Astroの構成を採用。

- `npm ls --depth=0` で依存関係を確認。インストール時の監査は脆弱性0件。
